# fix(world_segment): split fully-disconnected builds the closing over-merged

## 1. Offending build

`wol-project/samples/wol-sample-10.zip` → `d44bbed2cdad55d93551056046accb7b.schem`
(provenance: `world_bbox [[-2303,-63,-767],[-2050,38,-514]]` = 253×101×253, a
plot-scale region; `block_count 399456`, `cluster_count 1`). It is the "plot-scale
blob" residual class flagged in `06-m10-results.md`.

Connected-components analysis (**6-connectivity** on non-air voxels, air =
`minecraft:air`/`cave_air`/`void_air`):

|------|--------|------|-----------------------------|------|
| 0 | 184,427 | 46.2% | (4,12,4)→(194,50,109) | **build A** |
| 1 | 178,660 | 44.7% | (124,9,116)→(223,99,253) | **build B** |

Two substantial, fully spatially-disconnected builds (A, B) of nearly equal size
share one segment. **Minimum gap A↔B: 7 blocks Chebyshev (6 empty blocks) = 2
occupancy cells at `cell_size 4`.** This gap is the key number.

For contrast, the other 9 samples do NOT decompose into two ≥40%-share substantial
components: `7f16e3` (a legit single build) has a graded 33/13/11/9%… tail; `0065c8`
has 47/31/17%. Only `d44bbed2` is two comparable halves.

## 2. Merge mechanism (`segment.rs` / `grid.rs`)

`SegConfig` default: `cell_size C=4` blocks, `closing_radius R=2` cells. Step 2/3
dilates the per-partition occupancy grid by `R` (Chebyshev) and labels it with
6-connectivity, then `group_into` buckets the ORIGINAL cells by that dilated label.
Documented invariant: two occupied cells merge when within `2R` cells on every axis;
merge threshold `2R+1 = 5` cells, i.e. the closing **bridges gaps up to ≈`2R·C = 16`
to `(2R+1)·C = 20` blocks**.

## 3. Root cause (confirmed)

Builds A and B are 2 cells / 7 blocks apart — far inside the ≈16–20-block bridge.
The morphological closing dilated them into overlapping cell-cubes, 6-connectivity
fused those, and both builds received one label → one `ClusterId`. This is the
closing doing its intended job (unifying a single build's near-parts) but wrongly
applied across two separate builds. The floor slab (comp 3) is a red herring: A↔B
merge directly, without needing it. Confirmed: measured gap (2 cells) ≪ bridge (4–5
cells).

## 4. Fix

`src/world_segment/segment.rs`

New opt-in `SegConfig.split_disconnected: Option<DisconnectedSplit>` (default `None`).
After `assign_ids`, new step **3b** `split_disconnected_clusters` re-derives the
six-connected components of each merged cluster's **original (undilated)** cells and
splits the cluster iff it is really two-plus separate builds:

- a component is a **seed** iff `block_count ≥ min_component_blocks` (absolute floor)
  **and** `≥ min_component_share` of the cluster's blocks;
- split happens only with **≥2 seeds**, every seed pair **≥ `min_gap_cells`** apart
  (Chebyshev, exact-threshold test, not quadratic);
- each seed gets a fresh `ClusterId` anchored on its OWN lexmin cell (preserves the
  `assign_ids` anchor-injectivity invariant; the seed still owning the global lexmin
  re-mints the identical id); non-seed fragments attach to their nearest seed
  (centroid Chebyshev, ties broken on smaller anchor) — no debris, no lost blocks.

**Config knob + defaults** (`DisconnectedSplit::default`):
`min_component_blocks = 4096`, `min_component_share = 0.40`, `min_gap_cells = 2`.
At 0.40 at most two components can qualify, so a split needs the cluster to be two
comparably-sized masses — the two-builds signature. Applied to the sample: only
`d44bbed2` splits (A 46.2%, B 44.7%, both ≫4096, gap 2 ≥ 2) → 2 builds; all 9 others
untouched.

Folded into `config_hash` as a backward-compatible extension (17-byte framed part,
appended only when `Some`, after `partition_floor_share`) — every golden `ClusterId`
is byte-for-byte unchanged when disabled. Wired into `examples/wol_extract.rs` via
`--split-min-blocks` (default 4096; `0` disables), so future extractions get the fix;
`src/bridge/world_segment.rs` + the two full `SegConfig` literals in
`tests/world_segment_determinism.rs` carry the new field.

## 6. Residual risk / guard

Could it over-split a legitimate build? Only if that build's original cells form ≥2
six-connected components that are EACH ≥4096 blocks AND EACH ≥40% of the whole AND
≥2 cells apart — i.e. the build is essentially bisected into two comparable halves
with a genuine empty-cell corridor. The 0.40 share cap makes ≥3 seeds impossible and
makes a dominant-plus-fragments build (the common `7f16e3`/`0065c8` shape) safe. Two
big masses 2 cells apart remain genuinely ambiguous (the closing merged them for the
same reason); the operator can raise `--split-min-blocks` or the share to trade
recall for caution. Disabled by default in `SegConfig`, so nothing changes unless a
run opts in.

**Forward-looking:** builds already extracted into schemati stay merged until a future
re-extraction with the split enabled; this fix does not retro-split existing output.
