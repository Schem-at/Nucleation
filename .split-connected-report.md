# `UniversalSchematic::split_connected`

## API

```rust
// src/connectivity.rs
pub fn split_connected(&self, conn: Connectivity) -> Vec<UniversalSchematic>;
pub fn split_connected_min(&self, conn: Connectivity, min_blocks: usize) -> Vec<UniversalSchematic>;
```

Both are inherent methods on `UniversalSchematic`, added to the existing
`src/connectivity.rs` module (alongside `select_connected` / `connected_components`
from `e03837d`). No new module, no reimplemented flood-fill — both are thin
wrappers around `self.connected_components(conn)`.

## How it works

`split_connected`:
1. Calls `self.connected_components(conn)` (existing primitive — a shared-visited-set
   flood-fill over `NotAirMask::new(self)`), which already returns `Vec<Component>`
   sorted largest-first.
2. For each `Component`, builds a fresh `UniversalSchematic::new(...)` ("piece"),
   then for every `BlockPosition` in `Component::blocks`:
   - reads the source block via `self.get_block(x, y, z)` and writes it into the
     piece via `piece.set_block(x, y, z, &block)` — this carries the full
     `BlockState` (name + properties), since `BlockState` is cloned whole, not
     re-parsed from a bare name.
   - reads `self.get_block_entity_owned(pos)` (the existing position-aware,
     region-precedence-resolving accessor) and, if present, writes it into the
     piece via `piece.set_block_entity(pos, entity)`. Because this is driven by
     the component's own block list, a block entity only ever lands in the piece
     that owns its coordinate — no cross-component leakage is possible.
3. Compacts the piece's `default_region` via `Region::to_compact()` before
   returning it.

## Why the compaction step was necessary (found via TDD)

`Region::set_block`'s incremental `expand_to_fit` over-allocates the *storage*
bounding box (a `+64`-per-axis padding for small regions, for amortized-growth
performance) — it does **not** track a tight box on every write. Building a
piece purely with `set_block` calls left `UniversalSchematic::get_block`
reporting phantom `Some(air)` far outside the component's actual footprint
(the padded storage bbox), and `get_bounding_box()` returned that padded box
instead of the real one. This showed up immediately as a red test
(`split_connected_two_blobs_routes_blocks_and_block_entity_to_correct_piece`
failed: `piece_a.get_block(50, 0, 0)` was `Some`, not `None`, because piece A's
storage region had been padded out to x≈65).

Fix: each piece's `default_region` is replaced with `piece.default_region.to_compact()`
(existing Region method, already used by the exporters) after population. This
shrinks storage to the tight content bounds (blocks + entities + block
entities) while preserving `block_entities`/`entities`, giving each output
schematic a correct, non-padded bounding box.

## Coordinates & metadata

- **No re-origining.** Blocks are written at their original `(x, y, z)` — same
  coordinates as in the source schematic, including negative coordinates
  (`set_block`/`expand_to_fit` handle negative growth identically to positive).
  A caller that wants pieces normalized to `(0,0,0)` can do so afterward; this
  primitive intentionally preserves reversibility (union of pieces == original).
- **Metadata**: each piece starts from `self.metadata.clone()` (author,
  description, mc_version, etc. all carried over), then overwrites just
  `metadata.name` to `"{original_name}#{1-based index}"` (falls back to
  `"schematic#N"` if the source had no name). Index order follows
  `connected_components`'s largest-first order.

## Correctness tests (all in `src/connectivity.rs::tests`, TDD red→green)

- `split_connected_two_blobs_routes_blocks_and_block_entity_to_correct_piece` —
  two face-disconnected blobs (one with an NBT chest) split into 2 pieces;
  asserts the chest's `BlockEntity` (id `minecraft:chest`) is present in the
  piece owning that coordinate and **absent** from the other piece, and from
  the wrong coordinate in the right piece.
- `split_connected_honors_connectivity_choice` — a pure corner-diagonal touch
  (`(0,0,0)` / `(1,1,1)`) yields 2 pieces at `Connectivity::Face`, 1 piece at
  `Connectivity::Corner` — connectivity choice is honored end-to-end through
  `split_connected`, not just `connected_components`.
- `split_connected_block_conservation_round_trip` — **block-conservation
  assertion**: builds a mixed schematic (a `minecraft:oak_stairs[facing=north,half=top]`
  blockstate with properties, a disconnected singleton, negative coordinates),
  scans a superset volume for `(pos, block.to_string())` pairs before the
  split and across every returned piece after the split, sorts both, and
  asserts equality — proving no block lost, duplicated, or mutated (state
  included, since `to_string()` round-trips properties).
- `split_connected_min_drops_tiny_fragments` — a 5-block main mass plus a
  2-block fragment: `split_connected` returns 2 pieces, `split_connected_min(.., 3)`
  drops the fragment and returns 1 (the 5-block piece).
- `split_connected_single_component_returns_one_block_identical_piece` — a
  fully-connected 3×3 slab returns exactly 1 piece with the same
  `total_blocks()`, the same tight bounding box, and block-identical content
  cell-by-cell.

## Concerns / follow-ups (not blocking)

- `split_connected_min`'s doc explicitly notes tiny fragments are **dropped**,
  not merged into a neighbour — matches the spec ("attach-to-nearest is NOT
  required here").
- Multi-region inputs: `connected_components` already floods over the whole
  schematic's `get_bounding_box()` using `NotAirMask` (which itself resolves
  through region precedence via `UniversalSchematic::get_block`), so a
  component's blocks can originate from multiple source regions; each such
  component still collapses into one single-region piece (`default_region`),
  by design — consistent with "emit single-region pieces is fine" in the spec.
- Piece compaction changes the piece's *storage* bbox to be tight; it does not
  touch the *source* schematic in any way (`split_connected` takes `&self`).
