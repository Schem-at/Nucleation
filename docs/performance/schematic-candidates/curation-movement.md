# Movement library curation

Prepared 15 November 2026. This is static curation, not a new simulator or vanilla test result. Separate execution reports determine whether a candidate is functional.

The local [movement catalog](/Users/harrison/RustroverProjects/Nucleation-schematic-archive/curation/movement.json) covers all **117 schematic files** in the downloaded `slimestone-military` (46), `slimestone-ai` (63), and `casual-builds` (8) manifests. There are **111 distinct SHA-256 contents**, six byte-identical pairs, **12 source-labeled negatives**, and **20 prioritized test proposals**. Every entry joins the parent index by the exact `source` and `path` from its manifest. No downloaded schematic was changed.

Each row records mechanism tags and their evidence, source claims separately from observations, actual saved DataVersion, dimensions and volume, decoded block counts, piston/head states, block entities and entity types, and import/test gates. All bytes were checked against their existing manifest SHA-256 before Python NBT inspection. No Rust compilation, remote command or Minecraft execution was performed.

## Import distinctions that matter

**Marker blocks and trigger semantics.** In 51 X-com files, the saved schematic differs from a matching companion JSON only by red stained-glass marker blocks (legacy block ID 95, metadata 14; packed value 3679) omitted from the companion. For example, `simple_observer_engine.schematic` has seven blocks, its JSON has six, its trigger is `(0,1,1)`, and the omitted marker is `(0,1,0)`. The upward engine has nine versus eight blocks, and the caterpillar eight versus seven. Preserve both the original and an explicitly named marker-removed derivative; never silently replace one with the other. The catalog records exact differing positions and companion paths.

Companion `trigger` means a target used by the source simulator. It is **not** a specified player input or permission to inject an internal piston/observer event. The real vanilla external action still needs establishing. Numeric block IDs, metadata and optional SchematicaMapping need explicit conversion; missing DataVersion stays unknown.

**Entities and exports.** The Casual Litematic super-smelter contains two hopper minecarts; its Sponge export contains none and is one block narrower in Z. The author specifically requires rail ramp fixes and added carts for the WorldEdit export. The single/quad iron Litematics contain four/16 mobs; their Sponge exports contain none. The wool Litematic contains a sheep and hopper minecart; its Sponge export has neither. Treat each original export as its own initial state. Document any repair as a derivative.

**Machine size is not file size.** SMA `BS--1` has 43,252 placed blocks and 2,997 saved entities; the Choe Geon shell variant has 168,523 blocks and 1,233 entities. X-com `1797 onepointfive` has a 285×25×112 bounding box and 27,975 non-air blocks. The one-wide trencher is 206 blocks tall. These are later stress cases, not cheap first activation probes. Match actual world height/chunk coverage; the source’s own verification notes describe an offset/height error that made several simulators agree on the wrong outcome.

**Region and state preservation.** The SMA bidirectional half-engine file has two named regions. Do not flatten it by dropping one region or assume it is a single assembly. Many larger inputs contain extended piston heads. Preserve their exact states and placement order policy. No saved moving-piston blocks or block entities were found in these 117 inputs; this does not remove the need to validate movement created during execution.

For the first observer engine, use its companion trigger and, only in the named marker-removed derivative, change the observer’s front cell for one game tick. Capture 256 ticks and establish whole-assembly translated recurrence at corresponding cycle phases. For the upward engine and caterpillar, screen at most the six adjacent empty cells for one two-game-tick redstone-block pulse, each from a fresh initial snapshot. Freeze the actual reference-valid pulse before comparing engines. A timeout without recurrence is inconclusive unless the reference demonstrates a specific failure.

For X-com paired cases, establish one external recipe and apply it independently to both saved layouts/declared variants. Capture 600 ticks for flyer 11/12 and 31/30, and 256 for the valid/not-valid cycle pair. Retain an observed 1.21.11 contradiction of a historical source label rather than forcing the expected answer. For the observer-drop case, a 128-tick trace targets ordered observer pulses and piston landing states.

The SMA stepper/controller files contain no explicit lever or operating instructions. The catalog lists up to 64 currently empty cells immediately in front of observers, in deterministic coordinate order, with the full candidate count. These are **topology-derived discovery inputs**, not known controls. Test a one-game-tick temporary-block update in each candidate cell on a separate initial snapshot, capped at 128 ticks per trial. Once actual directional controls are established in vanilla, freeze a finite forward/reverse/up/down schedule and compare both displacement and whole-assembly states. An unsuccessful bounded scan does not establish that the design is broken.

The super-smelter proposal is a finite batch such as 16 iron ore and two coal, after identifying its input/fuel/output chests. Capture up to 2,400 ticks, including both saved carts, furnace progress, all inventories and eventual idle. Do not measure throughput until the exact input locations, recipe and vanilla result are recorded. For the vertical conveyor, first understand the empty mechanism, then add one explicitly positioned/fused primed TNT entity in a named derivative and capture at most 32 pre-detonation ticks. For the small bomber, capture 128 ticks including every TNT spawn/fuse/position; its filename’s “no entities” describes the saved input, not its runtime.

## Known-negative labels and promotion gates

The 12 source labels are `test_flyer_2`, `4`, `6`, `8`, `12`, `17`, `19`, `24`, `26`, `27`, and `30` with `_doesnt_loop`, plus `simple_not_valid_cycle_valid-piston`. They belong in regression selection, not successful-throughput denominators. Byte-identical duplicate files should not count as independent coverage.

Promotion requires exact initial-state import checks, one frozen finite external input schedule, and a fresh vanilla 1.21.11 reference. Compare tick-end blocks plus all relevant inventories, moving blocks and entities; retain ordered block/update records for optimized-versus-uncached comparisons. Test world growth/negative-origin variants after the ordinary orientation is understood. A repeating hash, motion count or agreement between two implementations of shared code cannot establish functional parity.

For inventory/item/TNT cases, the existing reference capture must include the required nested contents and entity state before it can prove the claimed behavior. Keep attribution and source licenses with the archive. The curation only labels existing local files and does not redistribute them.
